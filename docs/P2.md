# I. Inheritance and Change Notes

## 1. Inheritance: Reuse the P1 Foundation Layer

This phase **fully reuses** the following foundational infrastructure defined in the P1 design document. This document will not expand or rewrite them again:

1. **Project directory structure**: the project root, `config/`, `src/`, `src/utils/`, `src/models/`, `logs/`, `data/`, `tests/`, and `requirements.txt` all remain aligned with the P1 conventions;
2. **Unified Schema model layer** (`src/utils/schema.py`): all enums and Pydantic models such as `UserTier`, `QueryType`, `AttachmentType`, `QueryRequest`, `InferenceResponse`, `RoutingDecision`, `ModelSelection`, `ModelConfig`, `SystemMetric`, and `UserSession`, including their fields and `@validator` rules, **must remain unchanged**;
3. **Unified logging system** (`src/utils/logger.py`): the four-parameter `setup_logging()` + `get_logger(name)` factory;
4. **Metrics framework** (`src/utils/metrics.py`): the four instances `SYSTEM_METRICS`, `ROUTER_METRICS`, `INFERENCE_METRICS`, and `PIPELINE_METRICS`, together with their Counter/Gauge/Histogram definitions and label dimensions. **P2 may only add metrics and must not modify existing metric signatures**;
5. **Configuration management system** (`config/config.yaml` + `main.py _load_config` default-value injection): the existing 20+ section names and default values from P1 remain unchanged. **P2 only adds detailed internal field definitions under the `router` / `inference` sections, and does not add any new top-level sections**;
6. **FastAPI foundation** (the `LLMRouterPlatform` skeleton class in `main.py` + CORS / exception handling / lifecycle): only **append** the business endpoint `POST /route` on top of it, without modifying the base endpoints `/health`, `/status`, `/analytics`, and `/admin/*`;
7. **Global design principles and constraints** (P1 document §5): hard constraints C1~C5, design principles DP1~DP4, and high-level risk mitigation measures R1~R5 remain **fully applicable throughout**.

## 2. Newly Added Business Scope in P2

This phase delivers the project's **first externally serviceable MVP version**, implementing only one **core value chain**:

> **External HTTP caller → `POST /route` → routing decision (one of intelligent / round-robin / weighted / fallback) → multi-provider inference (at least one of OpenAI / Anthropic / vLLM needs to be ready) → return structured JSON response (including `query_id`, `response`, `model`, `tokens`, `cost`, `latency`, and `cached` fields)**

Within the main path above, the following business capabilities are newly added in this phase:

| Capability | Description |
|---|---|
| Query classification | Two-stage weighted fusion (regex patterns 60% + keywords 40%) + confidence threshold + GENERAL fallback, covering 10+ `QueryType` values |
| Token estimation | Multi-model tokenizer adaptation (`gpt-4` / `gpt-3.5` / `claude` / default `cl100k_base`) + word-count approximation fallback |
| Model routing | 4 strategies, rule-matching engine, capability match + permission match + token-limit filtering + composite scoring (success rate / latency / cost / priority / context) + cost estimation |
| Context compression | 4 algorithms (`semantic_graph` / `sketch_based` / `attention_based` / `sliding_window`) + parameterized compression ratio + sentence importance scoring |
| Response cache | Redis backend + `MD5(model:query:temperature:max_tokens)` key + TTL + hit/miss metrics |
| Multi-provider inference | Abstract base class + OpenAI Async client (retry + streaming + cost) + Anthropic Async (adaptation + streaming + cost) + vLLM HTTP + SSE streaming |
| Automatic degradation fallback | If the routed target model is unavailable, select a fallback model from an available provider by priority |
| Batch processing framework | `BatchProcessor` skeleton (dual trigger conditions: `size ≥ max_batch_size` **or** `wait ≥ max_wait_ms`) |
| API endpoint `POST /route` | Fully available, returns 8 key fields; failure returns HTTP 500 + detail |

By the end of P2, Slack / Streamlit UI, Kafka / ClickHouse, and K8s / Docker are not required. Developers or testers should be able to **set any one model API key + start the FastAPI service + send one curl request to see a real LLM response**.

# II. Main Development Body of P2

## 1. P2 Milestone Goals

### M1: Main E2E Path Available
- After configuring any one available API key (for example OpenAI), `POST /route` returns 200, and the JSON response body contains **9 top-level fields**: `query_id`, `response`, `model_name`, `tokens(input/output/total)`, `cost_usd`, `latency_ms`, `cached`;
- `response` must be a non-empty string and semantically be a reasonable answer to the input query, and `model_name` must match a model configured in `config.yaml`.

### M2: Routing Strategies Observable
- At least 3 routing strategies (`intelligent` / `round_robin` / `fallback`) can all take effect by modifying `config.router.routing_strategy`;
- After invocation, the counts of `ROUTER_METRICS.routing_decisions`, `INFERENCE_METRICS.requests_total`, and `cache_hits` / `cache_misses` must increase (verification may use the `/metrics` endpoint or inspect object attributes directly).

### M3: Main Path Fault Tolerance
- When a provider is disabled (for example by removing `OPENAI_API_KEY`), requests must not crash. The system should automatically fall back to another available provider; `cached=False` + empty `error` field + still return a normal response.

### M4: Context Compression and Cache Verifiable
- A very large context request triggers compression logs (`logs/llm_router.log` should contain `"Compressed context from ... chars"`);
- For the same `query` + same `temperature` + same `max_tokens`, the second request returns `cached=True` + `latency_ms` significantly lower than the first.

### M5: Foundation Layer Does Not Regress
- All acceptance points that passed in P1 (`/health` healthy, `/admin/services` count, `/admin/reload-config`, startup with a minimal `config.yaml`, and the 5 negative schema validation checks) must still all pass.

## 3. Detailed P2 Development Task List

### Task 3.1: Query Classifier

**File**: add `src/llm_router_part1_router.py` (implement within this file)

**Classes and methods to add / implement**:

- Class: `QueryClassifier`
  - Method: `__init__()` (initialize `patterns` / `tfidf` / state flags)
  - Method: `_init_patterns() -> Dict[QueryType, List[str]]`
  - Method: `async initialize()`
  - Method: `classify_query(query: str) -> Tuple[QueryType, float]`
  - Method: `_keyword_classification(query: str) -> Dict[QueryType, float]`

**Implementation essentials**:

1. **Regex pattern library** — configure 3~4 regexes for each of 9~13 `QueryType` categories:
   - `code_generation`: write code / write function / programming language names / `def class function` keywords;
   - `code_analysis`: debug / fix / optimize / bug / complexity;
   - `analysis` / `summarization` / `creative_writing` / `brainstorming` / `planning` / `math` / `reasoning`: each has its own business keyword combinations;
   - `patterns` should be stored in the form of `List[re.compile or raw pattern str]`, and during use, `re.findall` should match against `query.lower()`.
2. **Keyword scoring** — each category should have a list of 6~8 keyword tokens. After tokenizing the query, perform set matching. Score = hit count / total number of keywords.
3. **Two-stage fusion**: for each `QueryType`, `final_score = pattern_score * 0.6 + keyword_score * 0.4`;
4. **Confidence threshold + fallback**: if the best score > 0.1 (default threshold, hardcoded is acceptable), then return `best_type, min(best_score, 1.0)`; otherwise return `QueryType.GENERAL, 0.5`;
5. **Async initialization fallback**: if `sentence-transformers` fails to load, keep `_is_initialized=True` after a warning log, and do not block the main logic of `classify_query` (pattern+keyword is sufficient for P2; `sentence-transformers` is only future-proofing);
6. **Thread/coroutine safety**: the classifier only reads internal shared structures and does not mutate them, so it can be called directly without locking.

**Core constraints**:

- The `confidence` returned by `classify_query` must be in the valid range [0.0, 1.0];
- Empty strings / whitespace-only input should not raise exceptions (outer `QueryRequest` validation handles interception), but internal handling should return `GENERAL + 0.0`;
- No GPU dependency and no `torch` initialization for classification (only allow failed imports in `initialize` without affecting behavior).

### Task 3.2: Token Counter

**File**: `src/llm_router_part1_router.py` (same file, implemented after `QueryClassifier`)

**Class and methods**:

- Class: `TokenCounter`
  - `__init__()` → internally `self.encoders: Dict[str, Encoding]`
  - `_initialize_encoders()` → populate 4 encoder keys: `gpt-4`, `gpt-3.5-turbo`, `claude`, and `default(cl100k_base)`
  - `count_tokens(text: str, model: str = "default") -> int`
  - `_get_encoder_key(model: str) -> str`

**Implementation essentials**:
1. **Tokenizer mapping**: `gpt-4` and `gpt-3.5` use `tiktoken.encoding_for_model`; `claude` approximately uses the `gpt-4` encoder; `default` uses `tiktoken.get_encoding("cl100k_base")`;
2. **Fuzzy model-name matching**: in `_get_encoder_key`, `if 'gpt-4' in model_lower` returns `'gpt-4'`, and so on;
3. **Approximation fallback**: for any exception (`tiktoken` not installed, encoding failed, etc.) → catch it, then `return len(text.split()) * 1.3` rounded to an integer, with a warning log;
4. **Idempotence**: repeated calls with the same `text + model` must return the same integer.

**Core constraints**:
- Return type must be `int` and ≥ 0;
- Zero-length text must return 0 and must not raise an exception;
- In P2, the counter must be called in at least the following two places: router building `query_context`, and compressor estimating target length.

### Task 3.3: Core Model Router

**File**: `src/llm_router_part1_router.py` (same file, after `TokenCounter`, **core P2 class**)

**Add / implement**:

- Data class (`dataclass`): `RoutingRule(condition, models, fallback, weight=1.0)`
  - Method: `matches(query_context: Dict[str, Any]) -> bool`
- Data class (`dataclass`): `ModelSelection(model_name, confidence, reason)`
- Class: `ModelRouter(config: Dict[str, Any])`
  - Attributes: `self.models: Dict[str, ModelConfig]`, `self.routing_rules: List[RoutingRule]`, `self.classifier`, `self.token_counter`, `self.default_model`, `self.routing_strategy`, `self.model_stats`
  - `async initialize()`
  - `_load_models()` (instantiate `ModelConfig` from `config['models']` and store in `self.models`)
  - `_load_routing_rules()` (construct `RoutingRule` from `config['routing_rules']`)
  - `async route_query(request: QueryRequest) -> RoutingDecision`
  - `async _build_query_context(request) -> Dict`
  - `async _intelligent_routing(context) -> ModelSelection`
  - `_capability_based_routing(context) -> ModelSelection`
  - `_has_capability(model_config, query_type_value: str) -> bool`
  - `_check_user_access(model_config, user_tier_value: str) -> bool`
  - `_select_best_model(candidates: List[str], context) -> str` (composite scoring)
  - `_round_robin_routing(context) -> ModelSelection`
  - `_weighted_routing(context) -> ModelSelection`
  - `_fallback_routing(context) -> ModelSelection`
  - `_estimate_cost(selection, context) -> float`
  - `update_model_stats(model_name, success: bool, latency_ms: int)`
  - `get_model_info(model_name) -> Optional[Dict]`
  - `get_routing_stats() -> Dict`

**Implementation essentials**:

1. **Four routing strategies**:
   - `intelligent`: scan rules first; if any `rule.matches(context)` is True → take `rule.models ∩ self.models` when non-empty → call `_select_best_model` on the candidates → return; otherwise fall through to `_capability_based_routing`;
   - `round_robin`: maintain an incrementing counter `_request_count`, mod by `len(available)`;
   - `weighted`: weight = `1.0 / model_config.priority`, normalize, then use `random.choices`;
   - `fallback`: directly return `self.default_model`.
2. **Routing rule engine `RoutingRule.matches`**:
   - Simplified approach is allowed: `eval(self.condition, {"__builtins__": {}}, query_context)`;
   - Example condition strings (configured in `config.yaml` `routing_rules`):
     - `"query_type == 'code_generation'"` → prioritize model list with `gpt-4-turbo`;
     - `"token_count >= 5000"` → choose a large-context model;
     - `"user_tier == 'premium'"` → premium-exclusive model list;
   - If `eval` raises an exception → treat as non-match.
3. **Capability matching `_has_capability`**:
   - Build `capability_mapping`: `query_type_value → required_capability_list`;
   - Return `any(req in model_config.capabilities)`;
4. **User permission `_check_user_access`**:
   - `tier_priorities`: `free=3`, `premium=2`, `enterprise=1` (smaller means higher privilege);
   - `model_priority >= user_priority` (`priority` with larger numeric value means "available to a broader user base") → True;
5. **Token limit filtering**:
   - Directly filter by `context.token_count <= model_config.max_tokens`;
6. **Composite scoring `_select_best_model`**:
   - Scoring weights (must conform to the P2 convention):
     - success rate `success_rate × 40`;
     - speed `max(0, 20 - avg_latency_ms/100)` → max +20;
     - cost `min(1/(cost_per_token*1e6), 20)` → max +20;
     - priority `(10 - priority)*2` → max +18;
     - context compatibility `token_count <= max_tokens*0.8` gives +10, `<= max_tokens` gives +5;
   - Choose the highest score; preserve original order when tied.
7. **Cost estimation `_estimate_cost`**:
   - `estimated_output_tokens = min(input_tokens*0.5, context.max_tokens)`;
   - Return `(input+output)*model_config.cost_per_token`;
8. **`RoutingDecision` output object**:
   - All fields must come from the P1 Schema: `selected_model`, `query_type`, `token_count`, `estimated_cost`, `routing_reason`, `routing_time_ms`, `confidence`, `fallback_models` (optional list), `routing_strategy`, `user_tier`;
9. **`ROUTER_METRICS` instrumentation**:
   - Before `route_query` returns normally, call `ROUTER_METRICS.routing_decisions.labels(model, query_type.value).inc()`;
   - `routing_latency.observe(routing_time_ms / 1000)` (unit: seconds, matching Histogram second buckets).
10. **Exception fallback**:
   - The entire `route_query` should be under try/except: if an exception occurs → construct and return a `RoutingDecision(selected_model=default_model, query_type=GENERAL, confidence=0.0, routing_reason="Fallback due to error: ...")`, and **must not raise upward**;
11. **`model_stats` tracking**:
   - `update_model_stats` updates `total_requests` / `successful_requests` / `total_latency` → derive `success_rate` and `avg_latency`, which are then used by `_select_best_model`.

**Configuration items (must be defined in the `config.yaml` `router` section)**:

- `router.default_model`: string;
- `router.routing_strategy`: `intelligent|round_robin|weighted|fallback`;
- `router.models.{model_name}`: 7 fields as `provider/api_key_env/max_tokens/cost_per_token/priority/capabilities/gpu_memory_gb` (with `model_name` as the key);
- `router.routing_rules`: a list of `[{condition, models, fallback, weight}, ...]`.

**Core constraints**:
- `route_query` must be `async def` (even if internal steps are synchronous, it must remain compatible with callers awaiting classifier async initialization);
- The return value must strictly be `RoutingDecision` (a Pydantic Model), not a `Dict`;
- Do not write any global singleton; all `ModelRouter` state must hang off instance attributes;
- Classification failure, stats failure, and scoring failure must not affect request completion (at minimum return the default model).

### Task 3.4: Context Compression Module

**File**: the first half of a new file `src/llm_router_part2_inference.py`

**Classes and methods**:
- Data class (`dataclass`): `InferenceContext(request_id, user_id, model_name, start_time, token_count_input, compressed_context=False, cached_response=False)`
- Class: `ContextCompressor(config: Dict)`
  - Attributes: `compression_ratio` (default 0.3), `max_context_tokens` (default 100000), `method` (default `semantic_graph`)
  - `async initialize()`
  - `async compress_context(context: str, target_length: int) -> str`
  - 4 `async _XXX_compression(context, target_length)` methods
  - Helper functions: `_split_sentences(text) -> List[str]`, `async _score_sentences(sentences) -> List[float]`, `_extract_key_phrases(text)`, `_extract_keywords(text)`

**Implementation essentials**:

1. **Algorithm routing**: `method` may take `semantic_graph / sketch_based / attention_based / sliding_window`; any other value must uniformly fall back to `sliding_window`;
2. **`semantic_graph` (default)**:
   - Split into sentences → score sentences → take `top max(3, len(sentences)*compression_ratio)` high-score sentences, concatenate in original order; if too long, truncate and append `"..."`;
3. **`sketch_based`**:
   - Extract top 10 key phrases (two-word window frequency statistics) → split by paragraph → keep paragraphs containing any key phrase → truncate if too long; if empty, degrade to the first `target_length` of the original text;
4. **`attention_based` (simplified)**:
   - Score by paragraph + keyword density + length score → take top-ranked paragraphs and merge in original order;
5. **`sliding_window`**:
   - `start_part = context[:N//2]` + `"\n...[COMPRESSED]...\n"` + `end_part = context[-M:]`, with total length ≈ `target_length`;
6. **Sentence importance scoring**:
   - Length factor (10~30 words +2, >30 +1);
   - Hit count of important keywords (`important` / `key` / `main` / `crucial`...);
   - First sentence and last sentence +1;
7. **Parameterized compression ratio**: external caller computes `target_length = int(original_length * compression_ratio)`.

**Core constraints**:
- Any compression algorithm must guarantee `len(return_value) <= target_length + 30` (allowing a small separator overhead);
- If input is `None` / empty / shorter than `target_length`, directly return the original string;
- Initialization failure (missing `AutoTokenizer`, etc.) must not block the service; after a warning, the feature must still work (using text heuristics only, without tokenizer dependency).

### Task 3.5: Response Cache System

**File**: `src/llm_router_part2_inference.py` (after `ContextCompressor`)

**Class and methods**:
- Class: `ResponseCache(config: Dict)`
  - `self.enabled / ttl(default 3600) / max_size`
  - `async initialize()` (connect to Redis, if failed then `enabled=False`)
  - `async get_cached_response(cache_key: str) -> Optional[Dict]`
  - `async cache_response(cache_key: str, response_data: Dict)`
  - `generate_cache_key(request: QueryRequest, model_name: str) -> str`

**Implementation essentials**:

1. **Redis connection**: `redis.asyncio.Redis(host=localhost, port=6379, db=0, decode_responses=True)`; only if `ping()` succeeds is it considered enabled;
2. **Cache key construction**: `MD5(f"{model_name}:{request.query}:{request.temperature}:{request.max_tokens}")` (a 4-tuple, excluding `user_id` to maximize reuse);
3. **`get` / `set` semantics**:
   - `get`: hit → `json.loads` + `INFERENCE_METRICS.cache_hits.inc()`; miss → `cache_misses.inc()`;
   - `set`: `SETEX(cache_key, ttl, json.dumps(response_data))`; catch exceptions and do not raise;
4. **Full degradation**: if Redis does not exist / connection fails / package is missing → set `enabled=False` in `initialize`; `get`/`set` become no-op behaviors, and **must not block the main request path**.

**Core constraints**:
- Do not use Redis Cluster and do not use a custom serializer, to avoid unnecessary P2 complexity;
- Cache keys must not include sensitive fields (no `user_id`, no attachment content);
- Do not cache 500 / error responses (cache only normal `InferenceResponse` objects without `error`).

### Task 3.6: Multi-Provider Inference Engine

**File**: `src/llm_router_part2_inference.py` (after cache section, second half of the file)

**Classes and methods (core of P2, must be fully implemented)**:

1. **Abstract base class `BaseInferenceProvider(ABC)`**:
   - Method: `async initialize()`
   - Method: `async generate_response(request: QueryRequest, model_name: str) -> InferenceResponse`
   - Method: `async stream_response(request, model_name) -> AsyncIterator[str]`
   - Method: `get_health_status() -> Dict[str, Any]`

2. **`OpenAIProvider(BaseInferenceProvider)`**:
   - `initialize`: read `config.api_key` or `os.getenv(config.api_key_env)`; construct `openai.AsyncOpenAI(...)`; if no key, log warning and return False;
   - `generate_response`:
     - `@retry(stop_after_attempt(3), wait_exponential(mult=1, min=4, max=10))` (`tenacity`);
     - `messages = [system(context)] + [user(query)]` if `request.context` is not empty;
     - `client.chat.completions.create(model=, messages=, max_tokens=, temperature=, stream=False)`;
     - Construct `InferenceResponse`: fill `response_text` / `token_count_input(usage.prompt_tokens)` / `token_count_output(usage.completion_tokens)` / `latency_ms` / `cost_usd` / `provider="openai"` / `cached=False`;
   - `stream_response`: `stream=True`, `async for chunk` → yield `delta.content`;
   - `_calculate_cost(usage, model_name)`: based on pricing Dict configuration (`gpt-4-turbo` / `gpt-3.5-turbo` each with input/output per 1k pricing);
   - `get_health_status`: `status=healthy if self.client else unhealthy`.

3. **`AnthropicProvider(BaseInferenceProvider)`**:
   - `initialize`: `anthropic.AsyncAnthropic(api_key, base_url, timeout=60)`, skip if no key;
   - `generate_response`:
     - Same 3 retries;
     - `prompt = f"Context: {context}\n\nQuery: {query}"` when context is not empty;
     - `client.messages.create(model=, max_tokens=, temperature=, messages=[{role:"user", content: prompt}])`;
     - `response_text = content[0].text`; `usage.input_tokens/output_tokens` → token count;
     - `cost_usd` based on Claude pricing (`claude-3.5-sonnet` / `claude-3-opus`);
   - `stream_response`: `async with client.messages.stream(...) as stream: async for text in stream.text_stream: yield text`;
   - `health`: equivalent.

4. **`vLLMProvider(BaseInferenceProvider)`**:
   - `self.base_url = http://{config.host}:{config.port}`; `self.http_client = httpx.AsyncClient(base_url, timeout=300)`;
   - `initialize`: check `GET /health`;
   - `generate_response`:
     - `POST /v1/completions`, payload includes `model/prompt/max_tokens/temperature/stream=False`;
     - Missing `usage` fields default to 0; self-hosted `cost_usd=0.0`;
   - `stream_response`: SSE parsing, parse JSON from lines prefixed with `"data: "`, extract `choices[0].text` incrementally;
   - `health`: whether `http_client` exists.

5. **`BatchProcessor` (P2 skeleton is sufficient)**:
   - Attributes: `enabled / max_batch_size(default 32) / max_wait_ms(default 50) / pending_requests / batch_lock(asyncio.Lock)`;
   - Method: `async add_request(request, provider, model_name) -> InferenceResponse`:
     - If `enabled=False` → directly return `await provider.generate_response(request, model_name)`;
     - In P2, even when enabled, it may still directly pass through and does not need to implement actual batch merging yet (left for P8 optimization), but the interface must be defined stably.

6. **Core orchestration class `InferenceEngine(config, router: ModelRouter)` (final entry point of the MVP main path)**:
   - Composition: `context_compressor = ContextCompressor(config.compression or {})`, `cache = ResponseCache(config.cache or {})`, `batch_processor = BatchProcessor(config.batching or {})`, `providers: Dict[str, BaseInferenceProvider]`, `inference_stats`;
   - `async initialize()`:
     - `await compressor.initialize()`; `await cache.initialize()`;
     - For `openai/anthropic/vllm` in config respectively, instantiate provider → `await initialize()` → add to `self.providers[name]` only if successful;
   - `async process_query(request: QueryRequest) -> InferenceResponse` (**MVP core path, must strictly implement the following 7 steps in order**):
     1. `routing_decision = await router.route_query(request)` → `model_name = decision.selected_model`;
     2. Get `provider = _get_provider_for_model(model_name)`; if `None` → call `_resolve_available_model(model_name)` to return a fallback pair (replace `model_name` and `provider`);
     3. `cache_key = cache.generate_cache_key(request, model_name)` → `cached = await cache.get_cached_response()` → if hit, return directly as `InferenceResponse(**cached)` with `cached=True`;
     4. Compression: if `request.context` is not empty and its length > `compressor.max_context_tokens` → compute `target_length = int(len(context)*compressor.compression_ratio)` → compress and update `request.context` (**note: do not modify the `QueryRequest` instance field directly**; this step may create a shallow copy of the request or process in place, with creating a copy recommended before passing downstream), set `compressed_context=True`, and write logs;
     5. `response = await batch_processor.add_request(request, provider, model_name)` → `response.compressed_context = compressed_context`;
     6. `await cache.cache_response(cache_key, response.__dict__)`;
     7. `await _update_stats(...)`; `router.update_model_stats(model_name, success=not response.error, latency_ms=response.latency_ms)`; `INFERENCE_METRICS.requests_total.labels(model, response.provider).inc()`; `INFERENCE_METRICS.request_duration.labels(...).observe(inference_time)`; return `response`;
     8. Exception: catch `Exception` → `INFERENCE_METRICS.errors_total.labels(model=decision.model or "unknown", error_type=type(e).__name__).inc()` + router stats failure tracking + construct and return an `InferenceResponse` containing `error` (`cached=False`, `provider=error`, `cost=0`, `tokens=0`), and **must never raise 500 outside this layer**.
   - `async stream_query(request) -> AsyncIterator[str]`: route → `provider.stream_response`, on error yield an Error string;
   - `_get_provider_for_model(model_name) -> Optional[Base]`: get provider name from `router.get_model_info(model_name)["config"]["provider"]`, then retrieve it from `self.providers`;
   - `_resolve_available_model(requested) -> tuple[str, Base]`:
     - Prefer direct retrieval first; otherwise iterate through `router.models.items()` to collect `(model_config.priority, model_name, available_provider)`, sort them, and take the first highest-priority one; if no provider is available at all → `raise ValueError("No inference providers are available")`;
   - `get_health_status()`: return aggregated provider health + `cache_enabled` + `compression_enabled` + `inference_stats`;
   - `async shutdown()`: close all vLLM provider `http_client` instances + Redis client.

     a. `payload = await request.json()` (FastAPI-layer `Request` object);

          "query_id": qid,
