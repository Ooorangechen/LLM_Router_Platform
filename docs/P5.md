# I. Inheritance and Change Description

## 1. Inheritance: Reusing P1~P4 Foundations and Business Layer

This phase **fully reuses** the following infrastructure and business capabilities defined in the P1~P4 design documents:

1. **Directory Engineering Structure**: Project root, config/, src/, src/utils/, kafka/, clickhouse/, monitoring/, data/, logs/, tests/, scripts/, streamlit_ui/, docker/, .github/ all follow the P1~P4 conventions;
2. **Unified Schema Model Layer** (src/utils/schema.py): Enums and Pydantic models such as `UserTier`, `QueryType`, `AttachmentType`, `QueryRequest`, `InferenceResponse`, `RoutingDecision`, `ModelConfig`, `SystemMetric`, `UserSession` **remain completely unchanged**; P5 only adds dedicated schemas such as RequestState / PolicyResult / FeedbackRecord / QualitySnapshot in independent files;
3. **Unified Logging System** (src/utils/logger.py): `setup_logging()` + `get_logger(name)` factory; new P5 modules uniformly use `get_logger("policy")` / `get_logger("langgraph")` / `get_logger("quality")` / `get_logger("feedback")` naming for Loggers;
4. **Metrics Framework** (src/utils/metrics.py): Signatures of the 7 types of instances (`SYSTEM` / `ROUTER` / `INFERENCE` / `PIPELINE` / `RESOURCE` / `ALERT` / `HEALTH`) **remain unchanged**; P5 adds two new container classes: `POLICY_METRICS` (quota/SLA/budget) and `QUALITY_METRICS` (SLO/hotspot/feedback), instantiated at the end of metrics.py;
5. **Configuration Management System** (config/config.yaml + main.py `_load_config` default value injection): All top-level sections from P1~P4 remain unchanged; P5 adds four top-level sections (`policy`, `langgraph`, `quality`, `feedback`) and populates them in `_load_config`;
6. **FastAPI Foundation** (main.py `LLMRouterPlatform` class skeleton): External contracts for `/health`, `/status`, `/metrics`, `/admin/*`, and the basic `POST /route` endpoint are not modified; only new endpoints such as `POST /route/advanced`, `POST /feedback`, `GET /quality/dashboard`, and `GET /admin/policy/state` are **appended**;
7. **P2 Routing Inference MVP** (ModelRouter / InferenceEngine / `POST /route`): Internal implementation is not modified; P5's LangGraph graph nodes ("classify / compress / execute", etc.) **call router.inference existing methods via dependency injection** in their internal implementations to avoid code duplication;
8. **P3 Kafka+ClickHouse Pipeline** (KafkaProducerManager / KafkaConsumerEngine / ClickHouseWriter): Pipeline is not modified; ExecutionPolicy quota status can optionally support a dual-mode of "in-memory (default) + ClickHouse asynchronous persistence (optional)", but defaults to in-memory mode to avoid strong dependency on CH;
9. **P4 Monitoring Observability and Alerting** (SystemResourceCollector / AlertManager / Prometheus / Grafana): Internal implementation of modules is not modified; SLO violation counts in P5 QualityMonitor are written to QUALITY_METRICS, automatically exposed by P4's existing Prometheus `/metrics` endpoint; a new P5 rule added to AlertManager (SLO violation alert) can be appended via the `monitoring.alert_manager.rules_override` override method;
10. **Global Design Principles and Constraints** (P1 §5): C1~C5, DP1~DP4, and R1~R5 apply throughout.

## 2. New Business Scope in Phase P5

This phase delivers three enterprise-grade capabilities: **Multi-tenant Policy Governance + LangGraph State Graph Orchestration + Quality Feedback Closed-Loop**, upgrading the system from a "callable LLM" to a "controllable, auditable, and optimizable LLM platform."

The new business capabilities added in this phase are as follows:

| Capability Item | Description |
|---|---|
| RequestState Request State Model | State carrier running through the entire LangGraph pipeline: 6 major partitions (input → routing → policy → execution → result → metadata) with 30+ fields, accompanied by an `execution_path` audit trail |
| ExecutionPolicy Execution Policy Engine | Quota (Free/Premium/Enterprise three-tier daily + hourly quotas + resets), SLA latency target (10s/5s/2s), single-request cost budget upper limit ($0.01/$0.10/$1.00); `check()` one-time full check + `consume()` consumption accounting + `refund()` anomaly rollback |
| LangGraph State Graph Routing Engine | 7-node directed graph: classify → policy_check → [reject→END / compress] → select_adapter (P5 returns None placeholder) → execute → [failure→fallback→] → log; conditional edges; `execution_path` list tracking; CircuitBreaker (`failure_threshold=5, half_open_after=30s`) |
| `POST /route/advanced` Advanced Endpoint | Follows the full LangGraph path (including policy verification); returns enterprise-grade fields such as `execution_path` / `quota_remaining` / `budget_consumed` / `break_reason` (when rejected) |
| QualityMonitor Quality Monitor | Sliding window of 5 minutes via thread-safe `deque(maxlen=10000)` collection; `start_request`/`end_request` paired telemetry; SLO check (`error_rate≤5%` / `latency_p95≤3s`); model hotspot detection; 10s TTL stats cache; Prometheus instrumentation |
| FeedbackCollector User Feedback Collector | Four types: Like(+1)/Dislike(-1)/Rating(1-5)/Comment; tags + comment text; persistence in `data/feedback/feedback.jsonl` + `fcntl` file lock to prevent concurrent writes; `POST /feedback` endpoint; `GET /quality/dashboard` aggregates Top N positive / Top N negative queries by user/model |
| Dual Switches for Policy + Orchestration | `policy.enabled` + `langgraph.enabled` are independent; when LangGraph is disabled, `POST /route/advanced` returns 501 Not Implemented, but `POST /route` (P2 basic) is unaffected; when policy is disabled, LangGraph skips the `policy_check` node and proceeds directly |

At the end of P5, enabling `langgraph.enabled=true` + `policy.enabled=true` completes multi-tenant governance quota restrictions + `execution_path` auditing + feedback closed-loop; when all are disabled, P2 acceptance scripts pass 100%.

# II. P5 Phase Development Core

## 1. P5 Phase Milestone Goals

### M1: Dual Switches Toggleable Without Regression
- Starting services with `policy.enabled=false` and `langgraph.enabled=false`:
  - All 7 acceptance items in P2 §5.3~§5.9 PASS;
  - P3 §5.2 Pipeline OFF acceptance PASS;
  - P4 §5.2 monitoring OFF acceptance PASS;
  - `grep -cEi "policy|langgraph|quality_monitor|feedback" logs/llm_router.log` = 0.
- With `policy=true` + `langgraph=true`, but langgraph package not installed or Redis not started: service starts without crashing (import fallback + try initialize), and `POST /route` (P2 basic) still returns HTTP 200.

### M2: Multi-Tenant Quota and Budget Enforcement
- Daily/hourly quotas and single-request budgets for 3 tiers: see Task 3.2 default table;
- Constructing a Free user sending 101 consecutive daily requests → the 101st `POST /route/advanced` returns `policy_rejected=true`, `break_reason="daily_quota_exceeded"`, and `status_code=429` (HTTP layer) or 200 + success=false (business layer, either is acceptable, must be unified);
- Hourly quota sending 11 consecutive requests → the 11th triggers `hourly_quota_exceeded`;
- Premium user constructs a request with a single-request budget exceeding $0.10 (deliberately setting a huge max_tokens + temperature to trigger routing to an expensive model) → rejected with `budget_exceeded`;
- Exception refund scenario: inference throws an exception → fails after `consume()` accounting → `refund()` rolls back daily + hourly quotas by -1, and final quotas match the successful count.

### M3: LangGraph Execution Path + Circuit Breaker
- Response body after normal `POST /route/advanced` contains 10+ fields at the top level; where `execution_path: list[str]` looks like `["START","classify","policy_check","compress","select_adapter","execute","log","END"]`, with length ≥ 6;
- Manually making `execute` fail 5 consecutive times (all Providers unavailable) → circuit breaker `state=OPEN`, subsequent requests directly take fallback or `policy_rejected` (`break_reason="circuit_breaker_open"`); after waiting 30 seconds → `state=HALF_OPEN`, letting 1 probe pass → if still fails, returns to `OPEN`, if successful, turns `CLOSED`.

### M4: QualityMonitor SLO + Hotspot Detection
- After 100 consecutive successes + 6 failures (`error_rate ≈ 5.7% > 5%`), calling `quality_monitor.get_slo_status()` returns `slo_ok=false` + `slo_violations=["error_rate_threshold"]`;
- When a model sample count ≥ 10 and average latency > 5000ms → `get_hotspot_models()` returns the model name list;
- Prometheus `/metrics` endpoint contains: `quality_slo_violations_total`, `quality_hotspot_detected_total`, `quality_request_duration_seconds` at least 1 line.

### M5: FeedbackCollector Closed-Loop + `/quality/dashboard`
- For a query_id, calling `POST /feedback` submits `rating=5, comment="great answer"`; another query_id submits `rating=1, comment="bad"`; 2 lines appear in `data/feedback/feedback.jsonl`, file lock takes effect (100 coroutines writing concurrently without corrupting JSONL structure);
- `GET /quality/dashboard?window_minutes=60` returns:
  - `top_positive: [{query_id, rating, comment, model, user_id}]` (default 20 items, sorted by rating descending);
  - `top_negative: [...]` (rating ascending);
  - `snapshot: QualitySnapshot` (sliding window SLO, success rate, p95 latency, hotspot model list).

### Task 3.2: ExecutionPolicy Execution Policy Engine (Quota/SLA/Budget + Circuit Breaker)

**File**: New `src/llm_router_part5_policy.py` (or inside `src/llm_router_part5_langgraph.py`; but independent is recommended, so subsequent P7 can replace it with a distributed Redis version without altering LangGraph)

**A. Class `QuotaStore` (Quota State Persistence Abstraction Layer)**:
- Interface methods:
  - `async get_daily_quota(user_id: str, user_tier: str, date_str: str) -> int` (returns remaining quota integer);
  - `async set_daily_quota(user_id, tier, date_str, value: int)`;
  - `async incr_daily(user_id, tier, date_str, delta: int) -> int` (atomic increment, returns new value);
  - `async get_hourly_quota(user_id, tier, date_hour_str: str) -> int` (`YYYYMMDDHH`);
  - `async incr_hourly(user_id, tier, date_hour_str, delta: int)`;
  - `async snapshot_dump() -> Dict` (used to write to `data/policy_state/snapshot.json` for restart recovery);
  - `async snapshot_load(data: Dict)`;
  - `async flush_snapshot()` (periodic write to disk, default every 60 seconds in P5).
- **In-Memory Implementation (default `MemoryQuotaStore`)**: Internal `Dict[Tuple[user_id, date_str], int]` two Dicts + `asyncio.Lock` protection; `incr_daily`/`incr_hourly` uses `async with self._lock` for atomicity;
- **Redis Implementation (optional `RedisQuotaStore`)**: `INCR user:{user_id}:d:{date}` + `EXPIREAT` at 24:00 timestamp of the day; initialization failure → degrades back to MemoryQuotaStore, logs info, no exception raised.

**B. Class `CircuitBreaker` (Circuit Breaker)**:
- Attributes: `name` (generally by model_name or per-global), `state=CLOSED`, `failure_count=0`, `failure_threshold=5`, `half_open_after=30` seconds, `last_failure_at=None`, `_lock`;
- Methods:
  - `async acquire() -> bool`: CLOSED→True; OPEN and `now-last_fail > half_open` → `state=HALF_OPEN`→True; OPEN → False;
  - `async record_success()`: HALF_OPEN→CLOSED, `failure_count=0`; CLOSED→0;
  - `async record_failure()`: `failure_count++`; `>= threshold` → `state=OPEN`, `last_failure_at=now`; HALF_OPEN→OPEN;
  - `get_status() -> Dict`: name/state/failure_count/last_failure_at.
- P5 default: One circuit breaker per **model_name** granularity (dict name→cb), plus a `global` level CB for excessive global failures;

**C. Class `ExecutionPolicy(config: Dict, quota_store: Optional[QuotaStore] = None, cb_registry: Optional[Dict[str, CircuitBreaker]] = None)`**:
- Attributes: `self.enabled`, `self.default_tiers: Dict[str, Dict]` (default parameters for 3 tiers, see table below; can be overridden by `config.tiers`), `self.quota_store`, `self._cb_registry`, `self._cb_global`;
- Default Tier Table (hardcoded + config overridable):

| UserTier | daily_quota | hourly_quota | sla_target_ms | cost_budget_usd |
|---|---|---|---|---|
| FREE | 100 | 10 | 10000 | 0.01 |
| PREMIUM | 1000 | 100 | 5000 | 0.10 |
| ENTERPRISE | 10000 | 1000 | 2000 | 1.00 |

- Methods:
  - `async initialize()`: Selects RedisQuotaStore or Memory according to config; initializes `cb_registry` (default empty dict, creates model-level CBs on demand by request latency) + global CB; starts `_snapshot_flush_loop` background task dumping every 60s;
  - `async shutdown()`: Final `flush_snapshot` + cancels background task;
  - `_tier_config(tier: str) -> Dict`: Merges `default_tiers` + `config.tiers`;
  - `async check(state: RequestState) -> PolicyResult`:
    1. Computes today's `YYYY-MM-DD`, current hour `YYYYMMDDHH`;
    2. Queries daily remaining = `max(0, tier.daily - store.incr_daily(user_id, tier, date, 0))` (Note: checks with +0 without deducting first, deduction happens in `consume`);
    3. Hourly remaining computed similarly;
    4. `sla_target_ms = tier.sla_target_ms`;
    5. `cost_budget_usd = tier.cost_budget`;
    6. If `daily_remaining <= 0` → `break_reason = daily_quota_exceeded`, `passed=False`;
    7. Hourly checked similarly;
    8. `passed=True` → returns PolicyResult and populates before/after (before = remaining, after = remaining un-deducted);
  - `async consume(state: RequestState, policy_result: PolicyResult) -> PolicyResult`:
    - `store.incr_daily(user_id, tier, date, +1)` → `daily_after = daily_before - 1`;
    - `store.incr_hourly(user_id, tier, hour, +1)` → `hourly_after = hourly_before - 1`;
    - Returns new PolicyResult, state corresponding fields updated synchronously (responsible by caller);
  - `async refund(state: RequestState, reason: str = "execution_failure")`:
    - Called when execute fails or throws an exception, returns quota +1;
    - `store.incr_daily(user_id, tier, date, -1)` with lower bound limited to 0;
    - Hourly handled similarly;
  - `circuit_breaker_for(key: str = "global") -> CircuitBreaker`: lazily creates via `dict.setdefault`.

```python
    # Provide lightweight compatibility layer: write own SimpleStateGraph (P5 fallback) to avoid strong dependency on langgraph

```

**A. Unified State Container**: Passed to LangGraph using `TypedDict` form, node function signature `(state: dict) -> dict` (returning a dict will deep merge with original state), or converted internally to RequestState. P5 recommends choosing one of two ways:
- **Option A (Recommended)**: LangGraph uses TypedDict workflow, entry `invoke(RequestState)` converts to dict first, and exits convert back to RequestState;
- **Option B**: Set RequestState `model_config = ConfigDict(arbitrary_types_allowed=True, extra="allow")` so LangGraph uses Pydantic states directly.

**B. Node Functions (must strictly implement 7, each node name matches the string in `execution_path`)**:

| Node Name | Function Signature | Responsibility | Key Execution Steps |
|---|---|---|---|
| `classify` | `async def classify_node(state: dict) -> dict` | Calls P2 `QueryClassifier.classify_query` | 1. Convert to `query: str`; 2. `qtype, conf = classifier.classify_query(query)` synchronously or `await classifier.classify_query(query)` (depending on whether P2 is sync/async, wrapped via `asyncio.to_thread` in P5); 3. Return `{"query_type": qtype.value, "query_type_confidence": conf, ...}`; 4. `state.execution_path.append("classify")` |
| `policy_check` | `async def policy_check_node(state) -> dict` | Calls `ExecutionPolicy.check` + records | 1. If policy disabled → `passed=True, break_reason="policy_skip"`; 2. Else `result = await policy.check(state_obj)`; 3. Populate all `policy.*` fields; 4. `policy.policy_applied=True`; 5. **Does not consume quota** (waits until before execute to consume); 6. Append `"policy_check"` to `execution_path` |
| `compress` | `async def compress_node(state) -> dict` | Reuses P2 `ContextCompressor` (already inside InferenceEngine) | 1. If `context_text` is empty or compressor disabled → return `{}`; 2. Else `compressed = await inference_engine.context_compressor.compress_context(...)`; 3. Backfill `context_text=compressed`, `compressed_context=True`; 4. Append `"compress"` |
| `select_adapter` | `async def select_adapter_node(state) -> dict` | P5 placeholder node, fixedly returns empty | 1. No Adapter lookup; returns `{"adapter_name": None}`; 2. Append `"select_adapter"` to keep `execution_path` consistent |
| `execute` | `async def execute_node(state) -> dict` | Core execution node | 1. Check policy passed? Otherwise `raise PolicyRejectedError(break_reason)`; 2. **Call `policy.consume()` to deduct quota first**; 3. Check `circuit_breaker_for(selected_model).acquire()` → False: `record_failure` + raise `CircuitOpenError`; 4. Assemble `QueryRequest` object; 5. `response = await inference_engine.process_query(req)`; 6. If `response.error` → `await policy.refund()` + `cb.record_failure()` + return `result.success=False, error_type=...`; 7. Success `cb.record_success()`, backfill `result.success/tokens/latency/cost`; 8. Append `"execute"` |
| `fallback` | `async def fallback_node(state) -> dict` | Execute failure fallback once | 1. If state already has `fallback_used=True`, skip to avoid infinite loop; 2. `fallback_model = decision.fallback_models[0]` or `router.default_model`; 3. Re-execute using `fallback_model`; 4. Regardless of success/failure `fallback_used=True, fallback_model=...`; 5. Append `"fallback"` |
| `log` | `async def log_node(state) -> dict` | Unified logging + telemetry instrumentation + (optional) Kafka Publish Hook | 1. `logger.info(JSON(state.to_audit_log()))`; 2. `QualityMonitor.end_request(state)` (paired `start_request` called at entrance); 3. If pipeline enabled, `asyncio.create_task` publishes 4 Kafka messages (reuses P3 Hook); 4. Append `"log"`; 5. `state.total_elapsed_ms = (now - received_at).ms`; 6. Return `{}` |

**C. Conditional Edge Definitions (P5 Core Orchestration Logic)**:
1. Linear basic flow: `START → classify → policy_check`
2. **Conditional Edge 1 (`policy_check → compress` or `END`)**:
   ```python
   add_conditional_edges(
       "policy_check",
       lambda s: "reject" if (s.get("policy_check_passed") is False and s.get("break_reason") not in ("policy_skip", None)) else "pass",
       {"pass": "compress", "reject": "log"}  # Rejections also go through log for auditing, then END
   )
   ```
   - Then `log → END`
3. Passing flow: `compress → select_adapter → execute`
4. **Conditional Edge 2 (`execute → log` or `fallback`)**:
   ```python
   add_conditional_edges(
       "execute",
       lambda s: "success" if s.get("result", {}).get("success") in (True, None) else "failure",
       {"success": "log", "failure": "fallback"}
   )
   ```
5. `fallback → log` (regardless of whether fallback succeeds or fails, finally `log → END`)

**D. Class `LangGraphRouterOrchestrator(config: Dict, router: ModelRouter, inference: InferenceEngine, policy: Optional[ExecutionPolicy] = None, quality_monitor: Optional[QualityMonitor] = None)`**:
  - Attributes: `self.enabled`, `self.graph` (compiled StateGraph), `_policy_enabled`, `_quality_enabled`;
  - `async initialize()`: Builds graph + injects dependencies into all node function closures (`router`/`inference`/`policy`/`quality_monitor`) + `self.graph = builder.compile()`;
  - `async ainvoke(state: RequestState) -> RequestState`: Entrance converts dict → `compiled.ainvoke` → converts back to RequestState; any uncaught exception in any node → `try/except`, records to `state.metadata.node_errors`, fallbacks (if not already fallen back), finally forces routing to `log → END`;
  - `_node_inject_exception_handler(node_fn)`: Decorates all node functions with `try/except` writing to `state.node_errors`.

**E. Entrance Wrapper `IntegratedLLMRouter` (P5 Semi-finished product, provides only one method, to be refined in P6)**:
  - Combines router / inference / policy / orchestrator / quality;
  - Method: `async process_query_advanced(request: QueryRequest) -> AdvancedRouteResponse` (see Task 3.4 Schema);

**Core Constraints**:
- LangGraph import failure: Enables `SimpleStateGraph` simplified implementation, ensuring the same node execution order (not necessarily flexible branching with conditional edges, but capable of returning an `execution_path` of at least 6 step strings to satisfy M3);
- Node functions **must not import each other**, depending on orchestrator closure injection uniformly;
- Must guarantee the `log` node is executed under any circumstance (for auditing + quality_monitor pairing), forcing log logic execution even in mid-stream exceptions inside the orchestrator `ainvoke` finally block.

### Task 3.5: QualityMonitor Quality Monitor SLO Sliding Window + Hotspot Detection

**File**: New `src/llm_router_part5_quality.py` (first half QualityMonitor, second half FeedbackCollector)

**A. Class `QualityMonitor` (`config: Dict, alert_manager_ref: Optional = None`)**:

1. **Internal Data Structures**:
   - `_rolling_window: deque[QualityRecord]` (maxlen=10000, `collections.deque`; `threading.Lock` or `asyncio.Lock`, use asyncio in async environments);
   - `_stats_cache: Dict[str, Tuple[float, QualitySnapshot]]` (TTL 10s, key=window_minutes → (expire_ts, snapshot));
   - `_slo_targets: Dict` (default `error_rate=0.05, latency_p95_ms=3000`);
   - `_hotspot_threshold: Dict` (`min_samples=10, avg_latency_ms=5000`);
   - Auxiliary Pydantic: `QualityRecord(request_id, user_id, model, tier, success: bool, latency_ms: int, cost_usd: float, tokens_total: int, error_type: Optional[str], ts: datetime)`.

2. **Methods**:
   - `async initialize()`: Initializes deque + lock + background `_stats_cache_cleaner` (deletes expired entries every 30s);
   - `start_request(state: RequestState)`: Records `node_started_at["__quality"] = now`;
   - `end_request(state: RequestState)`: Extracts success/model/latency/cost/tokens/error_type from state → constructs `QualityRecord` → `append` to deque (exceeding maxlen automatically drops oldest); instruments `QUALITY_METRICS`:
     - `quality_requests_total{model,tier,status}` Counter
     - `quality_request_duration_seconds{model,tier}` Histogram (`latency_ms/1000`)
     - `quality_tokens_total{model}` Counter
     - `quality_cost_usd_total{model}` Counter
   - `_rolling_records(window_minutes: int) -> List[QualityRecord]`: Filters records where `ts >= now - N minutes` (deque sequential scan);
   - `_compute_snapshot(window_minutes: int) -> QualitySnapshot`:
     - `request_count = len(recs)`;
     - `success_rate = sum(r.success for r in recs) / N` (N=0 → 1.0);
     - Latency = `sorted(r.latency_ms for r in recs)` → p50/p95/p99 = `np.percentile` or hand-written sorted quantile;
     - `total_tokens` / `total_cost` = sum;
     - `slo_ok`, `slo_violations = []`; if `error_rate > 0.05` → append `"error_rate_threshold"`; if `p95 > 3000` → append `"latency_p95_threshold"`; `QUALITY_METRICS.slo_violations_total{violation}.inc()` if triggered for the first time;
     - `hotspot_models`: Grouped by model, each group with $N \ge 10$ and $\text{mean(latency)} > 5000$ → recorded; for each new hotspot, `quality_hotspot_detected_total{model}.inc()` (deduplicated by hour);
     - Returns `QualitySnapshot`;
   - `get_snapshot(window_minutes: int = 5, use_cache: bool = True) -> QualitySnapshot`:
     - If `use_cache=true` and `(now, key)` not expired → returns snapshot from cache; otherwise computes and writes back to cache (`expire_ts = now + 10s`);
   - `get_slo_status(window_minutes=5) -> Tuple[bool, List[str]]`: `snapshot.slo_ok`, `snapshot.slo_violations`;
   - `get_hotspot_models(window_minutes=15) -> List[str]`: `snapshot.hotspot_models`;
   - `async shutdown()`: Cleans up tasks;

### Task 3.6: FeedbackCollector Feedback Collector + `POST /feedback` + `GET /quality/dashboard`

**File**: Second half of `src/llm_router_part5_quality.py`, including cross-platform file lock wrapper

**A. Cross-Platform File Lock Wrapper**:
- File `src/utils/filelock.py` (new in P5, independently reusable):
  - Class `FileLock(path, timeout=10)`, implements `__aenter__/__aexit__` (async context manager) or synchronous `__enter__` using `asyncio.to_thread`;
  - Unix: `fcntl.flock(fd, LOCK_EX | LOCK_NB)`; on failure `asyncio.sleep(0.05)` loops retrying until timeout;
  - Windows: `msvcrt.locking(fd, msvcrt.LK_LOCK, 1)` or using `portalocker` (if available);
  - Total failure downgrade: direct write + atomic writes not guaranteed, but P5 acceptance requires `fcntl` to work on Unix (macOS/Linux).

**C. Class `FeedbackCollector(config: Dict, storage_path: str = "data/feedback/feedback.jsonl")`**:
- Attributes: `enabled`, `path`, `_lock: asyncio.Lock` (in-process secondary layer preservation, Python-level sequential writes);
- Initialization: `mkdir -p data/feedback/`; touches file if non-existent;
- Methods:
  - `async submit(record: FeedbackRecord) -> FeedbackRecord`:
    1. Validates comment length ≤ 2000; rating ∈ [1,5];
    2. `record.created_at = utcnow()`; generates `feedback_id` if empty;
    3. `line = record.model_dump_json() + "\n"`;

    5. `QUALITY_METRICS.feedback_submitted_total{type,rating}.inc()`;
    6. Returns `record`;
  - `async query(window_minutes: int = 60, user_id: Optional[str] = None, model: Optional[str] = None, min_rating: Optional[int] = None, limit: int = 100) -> List[Dict]`:
    1. Reads `path` in reverse order, filters window by `created_at`;
    2. If joining by model is required, map `query_id → model` stored in memory dict (QualityMonitor or state storage) or ClickHouse `query_logs`; P5 default: if ClickHouse is enabled (P3) then JOIN query_logs model_name, otherwise filter parameter is ignored (warning log);
  - `async get_dashboard_data(window_minutes: int = 60, limit: int = 20, quality_monitor: Optional[QualityMonitor] = None) -> Dict`:
    1. `positive_records`: sorted by rating descending / like_value=+1 taking `limit` → `top_positive`;
    2. `negative_records`: rating ascending / dislike → `top_negative`;
    3. `rating_distribution`: `Counter(rating for r in window_records if r.rating is not None)`;
    4. `snapshot = quality_monitor.get_snapshot(window_minutes)` (if passed);
    5. Summarizes `{top_positive, top_negative, rating_distribution, feedback_total, window_minutes, snapshot}`.

**D. Endpoint Implementation (2 new in `main.py`)**:
1. **`POST /feedback`**:
